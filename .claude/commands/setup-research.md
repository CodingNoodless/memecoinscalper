Set up the research system before any new strategy testing. Follow CLAUDE.md throughout (costs, no lookahead,
include rugged/dead tokens, paper only, token management). Do the steps in order. After each step: update
`lab/state_notes.md`, append a line to today's `Sessions/` note, run
`uv run python tools/lab.py brief --write D:/vault/tradeslave`, and commit with a message stating the result.
Vault = `D:/vault/tradeslave`. Never open `data/research/holdout/` in steps 1–6 except to write it in step 4.

1. **VAULT MAP.** Use subagents (`scribe` / `researcher`) to scan the vault with grep/find/frontmatter only, not by
   reading every note; `Research/Runner research/Sources` (12k notes) gets counted, not read.
   - The map already exists: `Map/Memecoin bot knowledge map.md` plus 18 `Map/Map - <topic>.md` notes, generated by
     `uv run python -m tradeslave.vault_map`. Run it first to refresh, and don't hand-edit `<!-- map:start -->` blocks.
   - Write `Map/Vault map.md`: a folder-by-folder table of what lives where, note counts, and entry points.
     Link it from the master map.
   - Add the missing MOCs in `Map/` (the existing ones are kept and extended, not duplicated):
     `Map - Strategies` (every `Strategies/` family note with status), `Map - Paper trades` (`Trades/`, bots M1–M13b
     plus the scoreboard), `Map - Data sources` (`Data & Infra/`, repo `data/` datasets), `Map - Brainstorms`
     (brainstorm and observation notes at vault root, `Strategies/Idea bank*`), `Map - Cost model` (point to
     `Map - Execution and costs`, extend if useful). J2 already has `Map - Creator launches (J)`: extend it.
     Research is covered by the existing topic maps: link them from `Map/Vault map.md`.

2. **FAILURE SUMMARIES.** From `Experiments/Experiments.md` (~100 rows) and `lab/registry.jsonl`, group every test
   from the past 3 weeks into strategy families (the A–Z letters in `Strategies/`, M1–M16 bots, Kalshi/perps/other
   markets). Run one subagent per batch of families. For each family write `Strategies/Summaries/<family>.md`:
   hypothesis, what was tested (data, n, period), results with numbers and labels (*measured* / *sourced* /
   *assumption*), why it failed or stalled, and links to the originals.
   Then write `Strategies/Lessons-Learned.md` (the single lessons file) with two lists: **dead** (don't retest, with
   the one-line reason and link) and **never tested properly** (why: too few trades, bad cost model, survivor-only
   data, etc.). Have the `skeptic` agent review the "never tested properly" list.

3. **COST MODEL.** Build `tradeslave/cost_model.py` (one function the backtests import), reusing what exists in
   `tradeslave/research/` (`sim.py`, `sb_cost.py`, `gas.py`, `latency_probe.py`, the paper bots' fill logic) instead
   of starting over. Components:
   - Fee: 1.25% per side (Rohit's locked worst case; pump.fun/PumpSwap tiers documented, not used to lower it).
   - Network + priority fees: 0.0003 SOL per tx, with any measured priority fee distribution.
   - Slippage as a function of position size vs. pool liquidity (constant-product math on reserves at the time of
     the trade).
   - Failed/late-tx rate and entry latency from the paper bots' logs.
   - Stop-exit gap (measured on M13b: median 6.8% below the stop, worst 10% at −64%).
   - MEV/sandwich cost as an explicit *assumption* if unmeasured.
   Add `tests/test_cost_model.py`. Document every number with its source and label in vault
   `Data & Infra/Cost model.md` and link it from `Map - Execution and costs`.

4. **DATA.** First inventory what already exists (`data/candles`, `data/c1`, `data/full_trades`, `data/long_paths*`,
   `data/runners`, `data/survivors`, `data/m13_candles`, `data/trades/history.jsonl` + `backfill.jsonl`, the
   history miner output). Report coverage: tokens, date range, and the share that rugged/died. Fill gaps only with
   free sources (public RPC history miner, existing Helius budget).
   Assemble memecoin OHLCV + liquidity (reserves) **including rugged/dead tokens** into `data/research/`. Split by
   token creation time: train 60%, validation 20%, holdout 20% (the most recent), with a 24 h gap between splits.
   Write `data/research/manifest.json` (sources, date ranges, token counts, rug share per split, file hashes) and
   `Data & Infra/Research datasets.md`. If the data is too thin for 300 out-of-sample trades in a family, say so.

5. **GATES.** Write `lab/gates.yaml`, then commit it on its own:
   - min_trades_oos: 300
   - profit_factor_after_costs: > 1.3
   - expectancy_ci95_lower: > 0 (bootstrap, ≥ 10k resamples)
   - max_drawdown: < 35% (compounded at 10% of equity per trade)
   - param_stability: profit factor stays > 1.1 with every parameter shifted ±20%
   - outlier_test: still profitable with the top 5% of trades removed
   - deflated_sharpe_prob: > 0.95 (trials = registry variants + `Project/Hypothesis count.md` tally for the family)
   - holdout_profit_factor: > 1.2
   - capacity: report the position size (SOL) where expectancy after `cost_model.py` slippage reaches 0
   Then write `tools/gate_check.py`: reads `lab/gates.yaml` and a trades file (`ret` per trade, net of costs), prints
   a PASS/FAIL table per gate, avg net return per trade vs. the 5% benchmark, and the git hash of `lab/gates.yaml`
   (refuse to run if it has uncommitted edits). Default mode scores train/validation only. `--final` scores the
   holdout once per registry id: it refuses if that id has already used it, logs the use in `lab/holdout_log.jsonl`,
   and prints ALL PASS only if every gate passes. Add `tests/test_gate_check.py` with a known-good and a known-bad
   synthetic series. These backtest gates are separate from the forward verdict rules in `tools/lab.py`.

6. **HYPOTHESIS REGISTRY.** Write 5–8 notes in `Strategies/Hypotheses/` (use frontmatter from CLAUDE.md). Each needs:
   the inefficiency; **who is on the losing side and why they keep losing**; entry/exit logic precise enough to
   code; the data it needs (must exist in `data/research/` train/validation); and the result that falsifies it.
   Skip anything listed as dead in `Strategies/Lessons-Learned.md`; "never tested properly" items are allowed.
   Run each past the `skeptic` agent, then rank by strength of economic reasoning (not by backtest numbers: no
   holdout or forward data is used to rank). Register each with `uv run python tools/lab.py reg add` (status
   `idea`). Write `Strategies/Hypotheses/Ranking.md` with the ranked list and one-line reasons.

**Stop after step 6.** Print a summary: what each step produced (files, commits), data coverage and rug share,
cost model numbers, the gate file hash, and the ranked hypotheses with the skeptic's main objection to each. Do not
start any backtest. I review the hypotheses before the long run.
